## Defects and integration conflicts resolved

- A publication `audience_id=0` sentinel conflicted with a proposed user FK; column normalization now precedes FK creation and rollback restores the old representation.
- A supporting index could not be removed before its FK; rollback now drops FKs first. Populated rollback and reapply actually passed.
- New vehicle presentation initially invented approval/capacity and selected an arbitrary car; final code derives them from the linked current approval/onboarding and vehicle fingerprint, while demo fallbacks remain visibly unverified.
- Whole-ride cancellation required captured injected service/idempotency variables, canonical trip/lifecycle state, one event and atomic refunds; tests exercise the endpoint.
- New publication seat variable required closure capture, and the mounted UI fixture needed the actual field. Both now pass runtime checks.
- Canonical approved-driver/trusted-route integration existed as shipped patches but was absent from running source. The focused reconciliation preserves ordinary legacy profile/routing checks and routes managed bookings through canonical segment admission.
- Model casts could alter campus-local schedule interpretation. Managed reads use persisted Asia/Kolkata wall-clock values, and fresh setup configures that timezone.
- Recurrence batch publication is scoped to an internal authorized context; ordinary creation limits are preserved. This is an existing-suite compatibility repair, not new Sprint 2 feature delivery.
- Python syntax compilation must not emit pycache into the source package before manifest checks. The proposed official workflow compiles in memory.
